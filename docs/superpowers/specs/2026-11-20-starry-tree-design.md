# starry-tree：星月夜里的视角藏字圣诞树 — 设计

日期：2026-11-20
状态：已实现

## 目标

一个静态网页：用梵高《星月夜》（1889）的笔触和配色画一幅会动的油画，主体是画面中央一棵柏树式的圣诞树。构图是程序生成的，不复刻原画布局。拖拽可以转动这棵树，转到某个隐藏角度时，树上的暖黄笔触恰好连成行书「了凡」，其他角度下它们只是树上零散的灯。

- 地址：https://heng-mei.github.io/starry-tree/ ，仓库 `Heng-Mei/starry-tree`。
- 无构建步骤，`index.html` + ES modules，three.js 放在仓库里。
- PC 和移动端都支持。唯一的交互是拖拽，页面上没有按钮、文字或 HUD。

范围内：开场作画动效、天空持续流动、拖拽转树（带惯性和吸附）、视角藏字、圣诞动效（螺旋光带、飘雪、转动散开、树顶星光环）、Bloom、按性能自动降档。
范围外：声音、镜头俯仰和缩放、键盘操作、WebGL1 兼容、任何界面控件。

## 画面

### 构图

镜头固定，画幅仍按原画比例约 1.25 : 1，但布局是程序生成的，用固定种子保证每次一样：

- 树在画面正中，从底部升到上方约 7/8 处，是全画最近、最暗的东西。
- 天空：
  - 一条横穿画面的起伏漩涡带，沿带随机排几个正反交替、大小不一的漩涡。
  - 星的位置随机（泊松采样），避开树和月亮，大小一大几小。
  - 月牙在左上角，外围有黄绿光晕。
  - 地平线上方有一条更亮的天光。
- 下方：起伏的山丘，最底下一条村庄带，零星黄色灯窗。

屏幕比例和原画不同时：横屏左右延伸天空；竖屏以树为中心裁左右。

### 笔触语法

每一笔是一个实例化四边形，形状在 shader 里程序生成，不用纹理：
- 两端收尖，中段饱满，宽度方向有刷毛沟槽（细条噪声）。
- 颜料高度从中脊向两侧递减，由此算出伪法线。光从左上方来，加一点高光，形成厚涂质感。
- 每笔的颜色在调色板基础上做小幅明度和色相抖动，模拟湿画法里相邻笔触互相带色。

各区域的笔触：

| 区域 | 方向 | 尺寸 | 颜色 |
|---|---|---|---|
| 漩涡 | 沿流场 | 中 | 钴蓝、浅灰蓝、偏灰的中绿 |
| 漩涡外的天空 | 大致水平，越往右越躁动 | 中到大 | 群青、深蓝 |
| 星光环 | 同心圆切向 | 小 | 由内向外：暗黄或橙点 → 白 → 浅绿 → 勿忘我蓝 |
| 月亮 | 弧向 | 小、厚 | 橙黄，外围黄绿 → 鸭蛋蓝 |
| 山丘 | 斜向 | 中 | 蓝 |
| 村庄 | 横竖斜的直线 | 小 | 灰、黑蓝、锈褐，灯窗用黄 |
| 树 | 火焰状向上卷 | 中到大 | 深绿、褐、深茄紫三色同时上 |

### 配色

实现时用 `tools/bake-map.py` 从维基共享资源的公有领域图（[Google Art Project 版](https://commons.wikimedia.org/wiki/File:Van_Gogh_-_Starry_Night_-_Google_Art_Project.jpg)，1280px）离线烘焙一张 128×101 格的 `assets/starry-map.png`（约 90KB）。每格有亮暗两种颜色（"破色"）和所属区域（天空、漩涡、山丘、村庄）。

运行时把每个区域的格子按亮度排序，当作该区域的调色板。笔触按程序构图算出所在区域和目标亮度（漩涡强度、天光、低频噪声），取亮度相近的格子，再在亮暗两色里随机选一个。所以颜色关系来自原画，位置不来自原画。笔触方向取解析流场，不取原画方向。

采样前先用的初值（[colorcombinations](https://colorcombinations.org/paintings/the-starry-night)）：`#28378D` `#344B91` `#5272A1` `#151919` `#272822` `#B19E2D`。

按面积算，黄色占比不到 1%，星星看起来大但面积很小。所以黄色笔触要少而亮，靠 Bloom 发光。

### 流场

流场是解析函数，在 shader 里直接算，没有状态纹理：

- 流函数 ψ(x, y) = Σ 高斯漩涡。
  - 两条 S 带由一串反向旋转的漩涡排列而成。
  - 每颗星、月亮各有一个小漩涡。
  - 再叠一层低幅 curl noise。
- 速度 = (∂ψ/∂y, −∂ψ/∂x)，无散度，笔触不会聚成团。笔触方向和漂移方向都取这个速度的方向。
- 漩涡大小按一大、数个中、很多小来分布。湍流统计是否符合 Kolmogorov 有争议，这里只借这个"多尺度叠加"的结构。

## 圣诞树

- 形状：柏树式的细长锥体，底宽约为高的 1/4，轮廓带火焰状的起伏。
- 笔触：几千到一万笔，铺在锥体表面和浅层内部。方向沿着向上盘旋的火焰线，用柏树三色。
- 挂饰：小号星光环，就是同心圆笔触，和天上的星同一套语法，零散挂在树上。
- 树顶：一颗带白色光晕的金星，对应原画中部那颗"晨星"。
- 树绕自己的竖轴转。天空、村庄、月亮不动。
- 螺旋光带：一串浅黄白的短笔触从树根螺旋绕到树顶。画完后有一段亮光沿光带往上走，约 7 秒一轮。
- 飘雪：白色厚涂小笔触，在树前方缓慢飘落、左右摆动。
- 转动散开：树转得快时，树身和灯的笔触沿径向散开，停下后聚拢。字因此只在静止或慢转时可读。
- 树顶星光环：金星点亮时放出一圈向外扩散、渐隐的笔触。之后每次对准藏字角度时再放一次（两次至少间隔 5 秒）。

## 视角藏字

### 字形

「了凡」用行书，笔画骨架是手写的三次贝塞尔曲线，坐标归一化到字框里。

- 了：乛 接 亅。两笔之间用牵丝相连，竖钩末端出锋。
- 凡：丿 → ⺄（横斜钩）→ 丶。点可以和前一笔的钩笔意相连。
- 每笔还有一条宽度曲线，控制起笔、行笔、收笔的粗细，包括飞白。
- 字的位置：竖排，居于树身中上部，在隐藏视角下占树高约 60%。

骨架数据放在 `js/glyph.js`，是纯数据加纯函数，不碰 DOM。

另有一个调字形用的开发页面 `tools/glyph.html`，平铺显示骨架和宽度，方便迭代。它会随站点一起部署，但首页不链接。

### 放置算法

隐藏视角定为树相对初始朝向转过 θ\* = 140°。这个角度在开场画面里看不到字，转大半圈才能找到。

1. 沿每笔骨架按弧长采样，相邻采样点之间生成一笔短油画笔触，笔触方向是骨架切线，宽度取自宽度曲线。笔触之间略有重叠和抖动，读起来是梵高式的一组短笔触，不是一条光滑的线。
2. 在 θ\* 下，从相机穿过每个采样点的屏幕位置打一条射线，求它和树锥体的进出点。在进出点之间随机取一个深度。
3. 把这一点变换回树的局部坐标存下来。笔触的世界尺寸按到相机的距离等比放大，保证从 θ\* 看它在屏幕上的大小与深度无关。
4. 笔触的两个轴（切向、宽度向）在 θ\* 下按屏幕方向算好，存成树局部坐标里的三维向量。树转开以后，这些笔触随树一起转，彼此错开、透视变形，字就散了。

字的笔触用暖黄色：印度黄、锌黄，带一点橙。树上另外撒同色同语法的"灯"笔触作干扰，数量和字的笔触相当，保证在其他角度下分不出哪些是字。

### 发现与吸附

- 对准程度 a 由 |yaw − θ\*| 算出：小于 3° 时 a = 1，大于 15° 时 a = 0，中间平滑过渡。
- a 越大，字的笔触越亮，干扰灯和螺旋光带越暗。这是唯一的反馈，没有文字提示。
- 字的笔触边缘做软化，发光交给 Bloom，不画成硬边的灯管。
- 背面的灯（转到树后面的）逐渐淡出，所以从正面看字不会和背面的灯叠在一起。
- 吸附参考 Apple WWDC18《Designing Fluid Interfaces》的做法：
  - 拖拽中不吸附，只在 θ\* 附近 ±7° 内让拖动略微变"重"，手感上像卡位。
  - 松手时按角速度投影惯性停点 yaw + v / 摩擦系数（指数衰减下的精确停点）。停点落在 θ\* ±18° 内，就改用临界阻尼弹簧滑向 θ\*，弹簧初速度就是松手时的角速度，没有速度断层；甩得较快时会略过目标几度再回来；否则照常惯性滑行停下。

## 交互

- 只用水平位移：拖动距离换算成树的角速度，PC 和手机的换算系数分开调。
- 松手后按指数衰减惯性继续转。
- 用 `setPointerCapture`，手指或鼠标拖出画布也不会断。
- 画布设 `touch-action: none`，页面不滚动、不缩放。
- 开场期间也可以拖动，作画不中断。
- 不监听键盘，不做双击、长按。

## 开场作画动效

总长约 11 秒，各处同时、随机地冒出来，不按区域依次画：

1. 0–4.5 秒：底色从画布米色过渡出来。天空、山丘、村庄的笔触按一张低频噪声图决定出现时间，一片片在各处同时长出来。星和月的光环由内向外长，起始时间随机。
2. 1.0–3.6 秒：树身和树上灯的笔触先出现在天空里，散成一团绕树轴旋转的星云。
3. 4.2–9.6 秒：星云螺旋汇聚成树，从树根往树顶依次落位。
4. 约 9.5 秒：树顶金星点亮，放出星光环。然后螺旋光带从下往上画出，雪开始飘。

每笔出现时沿长轴从 0 长到全长，刚画上时带一点湿光，随后变干。

`prefers-reduced-motion` 时跳过开场，直接显示完成的画，天空流动也减慢。

## 画完之后

- 天空笔触沿流场方向缓慢漂移，没有状态：
  - 每笔的位置 = 出生点 + 方向 × 相位。
  - 每笔的相位随机，生命周期两端淡出淡入，所以整体看不出循环接缝。
  - 漩涡带漂得比外围天空快。
- 星光环、月亮、村庄和山丘静止。树顶金星的光晕轻微呼吸，螺旋光带上有亮光上行，雪持续飘落。
- 树只在拖拽和惯性时转动。

## 架构

```
index.html            全屏 canvas、importmap、WebGL2 不可用时的一行纯文字说明
js/main.js            renderer、Bloom、固定相机、主循环、Pointer 输入、惯性与吸附、降档
js/layout.js          画面坐标、树的位置和轮廓、隐藏角度、旋转与投影（JS 与 GLSL 一致）
js/glyph.js           了凡骨架 + 变形画放置（纯函数，Node 可测）
js/strokes.js         程序构图；读取烘焙图做调色板；生成各类笔触：位置、方向、尺寸、颜色、出生时间、漂移、汇聚起点
js/brush.js           笔触 shader 与底色层
assets/starry-map.png 烘焙图
vendor/three.module.js、vendor/three.core.js   r187，jsDelivr 压缩版
vendor/addons/        EffectComposer、UnrealBloomPass、OutputPass 及其依赖
tools/bake-map.py     烘焙脚本（uv 运行）
tools/glyph.html      字形调试页
test/glyph.test.mjs
.github/workflows/pages.yml   照抄 tetris
package.json          只有 "type": "module" 和 node --test
```

渲染分五层，按顺序画，最后过一遍 UnrealBloomPass（只让亮于阈值的星、月、灯、字发光）：
1. 底色层：一张平面，按程序构图取色，开场时从画布米色过渡到底色。
2. 背景笔触：天空、山丘、村庄。
3. 树身笔触：不透明，写深度。
4. 灯层：字、干扰灯、螺旋光带、金星和星光环，预乘 alpha 加光晕。
5. 雪。

每层一个 `InstancedBufferGeometry`。开场汇聚、转动散开、雪的飘落和光带亮光都在顶点着色器里按时间算，没有逐帧的 CPU 更新。

## 性能

| 档 | 设备 | 笔触总数 | DPR 上限 |
|---|---|---|---|
| 高 | PC | 背景约 20,000 + 树 6,500 + 灯约 650 + 雪 500 | 2 |
| 中 | 手机 | 背景约 9,000 + 雪 350，树和灯不变 | 1.5 |
| 低 | 帧率仍不够 | 背景约 5,000 + 雪 250，树和灯不变 | 1 |

笔触越少，单笔越大（尺寸 ∝ (20000/n)^0.35），保证画面始终铺满。

如果连续 2 秒平均帧率低于 40 fps，就降一档。降档只减少天空和地景的笔触，字和干扰灯的数量保持不变，否则藏字会露馅或者读不出来。

## 验证

- `node --test test/glyph.test.mjs`：
  - 在 θ\* 下，所有字的笔触投影到屏幕后，离骨架的距离都在 ε 以内。
  - 在 θ\* ± 30° 下，投影后的平均偏离超过阈值，说明字确实散开了。
- 手动检查：`python3 -m http.server 8123`，用 PC Chrome、Safari 和 iOS/Android 真机：
  - 开场顺序正确。
  - 拖拽和惯性手感正常，吸附生效。
  - 在 θ\* 处字清晰可读，其他角度看不出字。
  - 竖屏构图合理，页面不滚动。
- 部署后用线上地址复查一遍。headless Chrome 访问本地服务时偶尔会断开模块请求，属于已知现象，不是代码问题。

## 已知取舍

- 只有树能转，天空是固定远景。
- 构图用固定种子生成，每次打开都一样。
- 流场是程序生成的解析漩涡，不是从原画提取的方向。
- 行书骨架靠手调，第一版的字形质量取决于迭代次数。
- 没有 WebGL1 兼容：不支持 WebGL2 的浏览器只显示一行文字说明。
- 低档仍保留字和干扰灯的全部笔触，非常弱的设备上帧率可能低于 30。
